# 2026.269.1424 — chore(deps): bump sdk to v0.2026269.1353 (the host-renderer fix, sdk#303)

## Summary

Bump the plugin's `github.com/opencharly/sdk` pin from `v0.2026241.2117` to
**`v0.2026269.1353`** — the merge of **opencharly/sdk#303**, which fixed the
host/machine-venue renderer, and **add the test that exercises that fix through
this plugin's own entry point**.

`deploy:local` is served by this plugin, which hands the compiled plan to
`sdk/kit.WalkPlans` (`candy/plugin-deploy-local/plugin.go`:

```go
reverseOps, err := kit.WalkPlans(ctx, exec, plans, kit.WalkOpts{})
```

). sdk#303 made the **host** renderer honour `unless_exists` and stop emitting
`install -d -m0755 ''` for an `extract: sh` download with no `to:`. Without the
bump this plugin still builds against the old SDK and the `target: local` venue
keeps failing on any candy whose plan has such a download step — `layer-kubernetes`'s
helm step is the concrete case:

```yaml
- download: "https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3"
  extract: sh
  unless_exists: /usr/bin/helm
  run_as: root          # no `to:` — the script installs itself
```

plan through a capturing `DeployExecutor`, and asserts the **emitted host script**:

- (b) contains `if [ -e '/usr/bin/helm' ]; then` — the `unless_exists` gate;
- (c) is valid `sh` under `sh -n` — the gate Terminator must parse.
